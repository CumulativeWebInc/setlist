Setlist

Playlist-pitching CRM + scan-verified placement tracker. A Cumulative Web Inc. product. Zero dependencies, Node ≥ 20.

The doctrine, in one line: the tool tracks, reminds, and verifies — it never auto-sends. Everything CWI runs manually to pitch tracks — curator CRM, submission threads, scan-verified placement proofs, follow-up scheduling — as real software.

Try it

git clone https://github.com/CumulativeWebInc/setlist.git
cd setlist
node seed.js                 # seed the real CWI dogfood corpus (60 curators, 35 pitches)
node setlist.js report       # pitches, placements, curator reply stats
node setlist.js queue        # today's follow-ups (capped at 20/day)
node setlist.js verify <playlist_url> <track_id> --file snapshot.json
npm test                     # 84 tests, node:test, zero deps

Curator CRM

Verified curator records — submission paths, reply history, payola flags. Paid placement routes are flagged and never pitched.

Evidence or it didn't happen

A placement needs a playlist URL plus a receipt. Link-first, scan-second. Unverified claims are rejected by the data layer, not by policy.

Anti-spam governor

One pitch per (curator, track), 2 follow-ups max ≥7 days apart, 20 outbound actions/day cap, one polite touch per thread.

Crash-safe store

Flat JSON envelopes, tmp-file → fsync → atomic rename. A corrupt file fails closed and loud.

Honest limits. Setlist records sends — it performs none. Playlist scans use snapshots you provide; it does not scrape Spotify. The seeded corpus is CWI's real 2026-09-14/15 operation; external results will vary. Free-submission routes only, always.
